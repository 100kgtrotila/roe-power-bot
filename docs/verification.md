# Перевірка перед першим хмарним запуском

Автоматичні тести не використовують справжній Telegram, акаунт Cloudflare або
мережевий запит до Рівнеобленерго. Інтеграційні сценарії працюють з локальними
workerd і D1 та підміняють тільки зовнішній HTTP.

## Фактичний результат 31.10.2026

| Перевірка                                    | Результат                                                             |
| -------------------------------------------- | --------------------------------------------------------------------- |
| `pnpm test`                                  | 127/127: 65 unit та 62 інтеграційних, усі пройшли                     |
| `pnpm run typecheck`                         | Пройшов без послаблення strict-перевірок                              |
| `pnpm run lint`                              | Пройшов                                                               |
| `pnpm run build`                             | Wrangler dry-run пройшов, без deploy                                  |
| `pnpm run dev --port 8791` та HTTP `/health` | Worker запустився, 200 з `{"status":"ok"}`; після перевірки зупинений |

Окреме рев'ю налаштування й планувальника виявило неточний опис зупинки cron та
втрату попередження про застарілу дату в наступних частинах довгого повідомлення.
Опис виправлено, для multipart-випадку додано тест із підтвердженим RED→GREEN.
Дата сумісності 2026-10-30 узгоджена зі встановленим локальним workerd.

Оновлення меню перевірене через справжній grammY routing з локальною D1:
постійна клавіатура, текстові кнопки, повернення, ✓, незмінність підписок під
час навігації та чесні стани перевірки сайту. Компактний графік зберігає всі
інтервали, ліміт довжини й походження даних у кожній частині.

Рев'ю нового формату виявило ризик зміни меж частин під час retry. Два D1-тести
спочатку відтворили пропуск тексту й втрату ще не надісланого intent; після
виправлення пройшли. Нова розбивка дозволена до першого надсилання. Після нього
текст прийнятого префікса та кількість частин мають збігатися, інакше залишок
скасовується без підтвердження повного графіка. Частково надіслану пряму відповідь
в такому разі можна запросити повторно. Нових міграцій або залежностей немає.

## Відповідність погодженій поведінці

Додатково перевірено відключення Telegram link preview на рівні фактичного API
payload та розділення HTTP/parse/request-помилок у контрольованих логах.
Сирий виняток із тестовим чутливим текстом не потрапляє в лог; пропущений за
розкладом запит не створює хибної події успішного розбору.

Номери відповідають рішенням у `superpowers/specs/2026-10-31-power-bot-design.md`.

безпечний вивід, помилки API та заборону getUpdates при активному webhook.

## Що залишається перевірити в реальному середовищі

- Власник створив D1, застосував remote migrations, задав секрети й allowlist.
- Реальний webhook приймає `/start`, кнопки, `/queue` та `/reminders`.
- Cron виконується, source_state оновлюється, свіжий графік потрапляє до кешу.
- Перший опублікований HTML з годинами відповідає граматиці парсера. Під час
  огляду джерела спостерігалося лише «Очікується»; фікстури годин синтетичні.
- Фактичний маркер «Відключень немає» звірений перед додаванням у парсер.
  Порожній або незнайомий текст не вважається скасуванням.
- Оновлення й нагадування доставляються у власний приватний чат.
- CPU і кількість запитів/рядків D1 вкладаються в обраний тариф. Локальні тести
  та dry-run не вимірюють хмарний CPU і не гарантують безкоштовний запуск.

Ці зовнішні перевірки потребують реального налаштування за [гайдом](deployment.md).
Ресурси, реєстрація webhook, платний тариф і повідомлення користувачам не були
частиною автоматичних перевірок. Коміти й push без запиту не виконуються.
