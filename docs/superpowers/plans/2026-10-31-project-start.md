# ROE Power Bot: початковий каркас

> Виконання: у поточній сесії за прямим запитом користувача створити початок проєкту.

**Мета:** підготувати перевірений TypeScript/grammY Worker і правила подальшої розробки.

**Архітектура:** HTTP-маршрути Worker окремо від фабрики grammY-бота. Початкові
команди пояснюють стан проєкту; парсер і сховище додаються наступним етапом.

**Стек:** pnpm, TypeScript strict, grammY, Wrangler, Vitest, Biome.

**Специфікація:** `CHAT_CONTEXT.md`; обсяг цієї ітерації — каркас, а не готова розсилка.

## Обмеження

- Не створювати хмарні ресурси й не налаштовувати реальний Telegram webhook.
- Не підміняти вибір підчерги тимчасовим in-memory сховищем.
- Не вмикати cron до реалізації парсера та збереження стану.

## Ризики для перевірки

- Невірний шлях/метод не запускає Telegram API.
- Відсутній secret не відкриває webhook без перевірки.
- Невірний secret не обробляє update.
- Команди у групах не створюють особистої підписки та не відповідають.
- Сирі помилки не розкривають BOT_TOKEN через HTTP або журнал.

## Наступні етапи

1. Парсер зі збереженими HTML-фікстурами та валідацією структури.
2. D1, міграції, вибір підчерги, `/schedule`, `/all`, `/stop`.
3. Спільний cron, порівняння графіків, контроль повторів і відкладені спроби.
4. Повний український гайд BotFather → D1 → secrets → deploy → webhook → перевірка.
